# C02 — Knowledge layer (criteria, exclusion ledger, registry, autonomy log)

## Purpose
The lab's learning is file-based, not weight-based (Sept 23 doc §1, constraint 2). This
component is where experimental skill accumulates: the rules every screen loads, the
binding negatives every screen must engage, and the log that decides when supervision drops.

## Owner role(s) and human touchpoints
`lab-archivist` writes (only via `/qml-promote` PRs). `screen-analyst` reads (G0).
Humans: Adi reviews ledger seed entries in W0; any of the 3 merges promote PRs (CP5);
quarterly ledger review by Adi + Tsahi (expiry sweep).

## Artifact schemas

### `criteria/lab_method.md` — sections
1. **The six rules** (from `INSIGHTS.md` §1–6) — each with: the rule, the painful specific that
   produced it (keep the numbers: 424× at N=2³⁰, 0.51 ROC-AUC leakage, +18% smoke point →
   1/3), the screen question it becomes, and red/amber/green criteria.
2. **Gate ladder G0–G9** with phase attachment (table from `01` §3).
3. **Adi's global rules 1–10** (pause at gates, criteria before runs, N and q everywhere,
   classify scaling, simulation ≠ quantum cost, strongest baseline fairly tuned, statistics,
   reproducibility, decision log, honesty about bad results).
4. **Scaling-warning table** (Adi S0 §3) — the five observations and the exact warning text,
   plus the break-even N* requirement.
5. **Simulation-limits table** (Adi overview §4) — statevector / density matrix / trajectories /
   MPS / Clifford.
6. **Negative Verdict Standard N1–N5** and the verdict vocabulary (D10).
7. **Glossary** (Adi overview §5 + claim ladder pointer to `SOUL.md`).

Format mirrors `criteria/qml_domain.md` so skills inject it the same way (`LAB_METHOD`
placeholder per `protocol.md`).

### Exclusion ledger entry (YAML blocks in one markdown file, one `##` per entry)
```yaml
id: polylog-pauli-graph-hamiltonian-recsys-ranking
status: final                 # final | provisional
verdict_ref: experiments/spectral_graph/06_node_correspondence_realdata/VERDICT.md
mechanism: >                  # structural, one paragraph
excludes: >                   # narrowest class the mechanism licenses
does_not_exclude: >           # mandatory, non-empty
covered_cases: []             # variants that failed the same gate by the same mechanism
evidence: [exp-04, exp-06, exp-09, exp-11]
audit: CONFIRMED              # CONFIRMED | legacy-human (seed entries) | INSUFFICIENT (provisional only)
reopening_condition: >        # required when provisional
review_by: 2027-09-30         # or trigger: "on evidence of type X"
blocks: quantum-spend         # provisional entries: quantum-spend only, never the reopening experiment
```

### `autonomy-log.md`
One table, append-only:
`date | program | checkpoint | mode | author | signer | outcome | minutes | note`.
Footer section regenerated by `/qml-lab stats`: per checkpoint — runs, consecutive
0-material streak, eval status, eligible-for-step-down yes/no.

## Procedure
**W0 seeding** (the single highest-value build step — prevents re-proposing measured ideas):
1. For each closed thread (01–13; materials M00/M01 once located) read `VERDICT.md` (in
   `qml_artifacts/experiments/` after C11). *Pass:* one draft entry per verdict.
2. Merge entries that share a mechanism (e.g. exps 04/06/09/11 → one polylog-Pauli recsys
   entry with `covered_cases`). *Pass:* every entry has non-empty `does_not_exclude`.
3. Mark seed entries `audit: legacy-human`, `review_by` = 12 months.
4. Adi reviews 3 random entries → logged in autonomy-log as CP5 rows (starts the counter).

**Steady state:** only `/qml-promote` (C08) edits the ledger, via PR. Quarterly: `/qml-lab
ledger-review` lists entries past `review_by` → human decides renew / reopen / retire.

## Checkpoints and autonomy
Ledger and criteria writes are **CP5** — permanent `HUMAN_APPROVE` (they prune everyone's
search space). Autonomy-log writes are mechanical (no checkpoint).

## Separation / permission rules
- The archivist copies and links; it never re-interprets or widens an exclusion.
- `lab_method.md` changes only by a human commit; the system may only *propose*.
- G0 must **engage**: `SCREEN.md` names each brushed entry and argues same/different by
  mechanism. "Different words" is not different.

## Failure modes and controls
| Failure | Control |
|---|---|
| Over-pruning via topic-scoped entries | `excludes` must be mechanism-scoped; `does_not_exclude` mandatory; eval 3 |
| Ledger ossifies | `review_by` mandatory; quarterly sweep |
| G0 becomes a formality | G0 is a required `SCREEN.md` section, checked by C10 harness |
| Rules lose their specifics when turned into a checklist | Keep the numbers and precedents inside each rule; eval 1 known-answer checks |

## Evals that cover it
Eval 1 (screen replay uses the ledger with entries *after* the replayed experiment removed —
time-sliced), eval 3 (false-kill), structural check: every ledger entry validates.

# C01 — Artifacts, state & thread layout

## Purpose
Define every file the lab reads or writes, so each skill has a contract and each handoff is
artifact-only (the failure-mode control for context contamination). Makes one rule
mechanical: **every skill reads `STATE.json` first and writes it last.**

## Owner role(s) and human touchpoints
Owned by `lab-director` (state) and `lab-archivist` (templates). Humans touch state only through
checkpoint sign-off (C09), which writes `STATE.json.checkpoints[*]` and `decision_log.md`.
Tsahi owns template changes (C10 improvement loop).

## Inputs / outputs
Input: nothing (foundation). Output: templates in `qml_researcher/artifacts/lab/`, JSON schemas
in `qml_researcher/artifacts/lab/schemas/`, and the layout below.

### Thread layout (one program = one thread = one branch `lab/<thread>` — D8)
```
qml_artifacts/experiments/<thread>/
  README.md                    program summary (generated by /qml-lab, human-editable)
  STATE.json                   control state — C01 schema
  00_inputs/                   algorithm paper/notes/code, or source card links
  HYPOTHESIS.md                /qml-intake — both paths
  ALGORITHM_ANALYSIS.md        /qml-intake — algorithm path only (Adi S0 report)
  SCREEN.md                    /qml-screen
  PROPOSAL.md                  /qml-prereg — narrative design (Adi S1 structure)
  00_operating_point.md        /qml-prereg
  frozen_definitions.md        /qml-prereg — splits, metrics, instance generators, seeds
  PREREG.lock.json             scripts/lab/lock.py — never hand-edited
  PANEL_1.md  PANEL_2.md       /qml-review-panel
  P1_toy/  P2_medium/  P3_real/  P4_noise/  P5_hardware/
      src/  raw/  figures/
      data/  manifest.json + fetch.py; files ≤ 5 MB committed, larger gitignored (C11)
      RUN_LOG.md               /qml-run
      provenance.json          scripts/lab/provenance.py
      results/gates.md         numbers vs thresholds only
      PHASE_REPORT.md          /qml-run (Adi S3 template)
  VERDICT.md                   /qml-verdict — frontmatter is the experiment's graph entity (C11 schema)
  AUDIT.md                     /qml-audit
  VARIANTS.md                  /qml-variants
  briefs/DECISION_BRIEF_<cp>_<n>.md   /qml-lab
  env.md  decision_log.md  change_log.md   (Adi overview §3, kept)
```
Legacy threads (01–13) are copied into `qml_artifacts/experiments/` by C11 with their existing
layout (plus entity frontmatter and data manifests); they do not get the new lab files. C02
seeds the ledger from their `VERDICT.md`s.

## Artifact schemas

### `STATE.json`
```json
{
  "schema": "qml-lab/state@1",
  "thread": "fraud_aml/14_example",
  "branch": "lab/fraud_aml-14_example",
  "owner": "meir",
  "entry_path": "algorithm | use-case",
  "frozen_question": "one sentence, copied from HYPOTHESIS.md after CP2",
  "stage": "intake | screen | prereg | run | verdict | audit | variants | promote | closed",
  "current_phase": "P1 | P2 | P3 | P4 | P5 | null",
  "checkpoints": {
    "CP1": {"mode": "HUMAN_APPROVE", "status": "open|approved|rejected|n/a",
            "author": "agent:screen-analyst", "signer": "adi",
            "outcome": "unchanged|minor|material", "minutes": 20, "at": "2026-10-02"}
  },
  "lock": {"sha256": "…", "amendments": 0},
  "budget": {"planned": {"cpu_h": 40, "tokens_m": 5, "wall_days": 5},
             "spent":   {"cpu_h": 12, "tokens_m": 1.2, "wall_days": 2}},
  "blockers": [{"what": "…", "command": "…", "since": "…"}],
  "escalations": [{"type": "budget_2x", "to": "adi", "brief": "briefs/…", "status": "open"}],
  "updated_by": "/qml-run", "updated_at": "…"
}
```
Checkpoint `mode` is copied from `config/lab_autonomy.json` when the checkpoint opens and not
changed afterwards (a step-down mid-program never loosens an open checkpoint).

### `PREREG.lock.json`
```json
{
  "schema": "qml-lab/lock@1",
  "locked_at": "…", "locked_by": "adi", "git_commit": "…",
  "items": [
    {"id": "P1.G4.threshold", "kind": "threshold|gate|split|stop_rule|metric|baseline|gray_zone",
     "text": "canonical text copied from PROPOSAL.md", "sha256": "…",
     "source": "PROPOSAL.md#L120"}
  ],
  "root_sha256": "hash over sorted item hashes",
  "amendments": [
    {"n": 1, "date": "…", "touches": ["P3.G6.threshold"], "reason": "…",
     "precedes_data_access_for": "P3", "approved_by": "tsahi", "new_root_sha256": "…"}
  ]
}
```
Rule: an amendment is valid only if its date precedes the first `provenance.json` timestamp
of the phase it touches — checked by `lock.py verify` (C06).

### Markdown templates (in `artifacts/lab/`)
| Template | Required sections | Derived from |
|---|---|---|
| `HYPOTHESIS.md` | Claim (contradictable by a number) · Operating point · Disproof sentence · Arm that wins if false · Decision it changes · **H1..Hn table** (hypothesis, predicted value/scaling, metric, source) · entry path | Tsahi §3.1 scoping + Adi S0 §4.9 |
| `ALGORITHM_ANALYSIS.md` | Adi S0 §4 sections 1–10 verbatim, warning boxes at top, N↔q mapping, resource tables | Adi S0 |
| `SCREEN.md` | G0 ledger engagement (required, not a lookup) · G1–G3 green/amber/red + reason · 5 QML criteria · architecture enumeration · warnings · verdict + narrowest licensed claim | Tsahi §4.1 |
| `PROPOSAL.md` | Adi S1 §3 structure + gray-zone policy per gate + both verdict sentences + budget per phase | Adi S1 + Tsahi §3.1 |
| `PANEL_n.md` | Per persona: issues (BLOCKING/NON-BLOCKING, verbatim anchor, fix) · Adi S2 checklist marks · verdict APPROVED / APPROVED-WITH-CHANGES / BLOCKED | Tsahi §3.1 + Adi S2 |
| `results/gates.md` | Table only: gate · measured · threshold · pass/fail · provenance id. No prose. | Tsahi §4.1 |
| `PHASE_REPORT.md` | Adi S1 §4 template (what ran + deviations · results · expected vs observed per H · baselines · surprises/possible bugs · gate decision) | Adi S1/S3 |
| `VERDICT.md` | Entity frontmatter (C11: id, aliases, thread, verdict, topics, audit, ledger) · Outcome (D10) · gate-by-gate by reference · mechanism · licenses / does-not-license · **"not shown in tested range" vs "shown absent"** · advantage type + confidence (GO only) · what survives regardless · reopening condition | Tsahi §4.1 + Adi S4 |
| `AUDIT.md` | Lock diff result · recomputed numbers table · reproduction table (Adi S5) · provenance sample · N1–N5 · alternative explanations · CONFIRMED/OVERTURNED/INSUFFICIENT | Tsahi §4.1 + Adi S5 |
| `VARIANTS.md` | Mechanism · ≤5 variants (generator, newly-passed gate, newly-faced gate, predicted kill gate) · salvage (a/b/c) · Adi S6 Q1–Q5 · recommendation | Tsahi §8 + Adi S6 |
| `DECISION_BRIEF.md` | ≤1 page: what is being decided · the agent's recommendation · evidence links · what it would cost to continue · 2–5 options · reply format | Meir §7 + Adi rule 1 |

## Procedure
1. W0: write templates + schemas; add `scripts/lab/validate.py` (C06) that validates
   `STATE.json`, `PREREG.lock.json`, `provenance.json` against the schemas. *Pass:* validator
   accepts a hand-built example thread and rejects 5 seeded-broken variants.
2. Every skill's Phase 0 = `validate.py STATE.json` + read; last phase = write + validate.
   *Pass:* a skill that exits without writing state fails C10's harness.

## Checkpoints and autonomy
None of its own. Enforces that each checkpoint's `mode` and `outcome` are recorded.

## Separation / permission rules
Write permissions per file are in C03's matrix. Hard rules restated here because they bind
the file layer: `PREREG.lock.json` is written only by `lock.py` invoked from `/qml-prereg`
(freeze) or `/qml-lab amend`; `results/gates.md` has no prose; `VERDICT.md` is never written
by the `implementer`.

## Failure modes and controls
| Failure | Control |
|---|---|
| Skill loses context between sessions | Read-first/write-last on `STATE.json` |
| Two people advance the same program | Branch per program; `owner` field; `/qml-lab` refuses if `git config user.name` ≠ owner unless `--takeover` (logged) |
| Hand-edited lock | `root_sha256` mismatch detected by `lock.py verify` at every CP3/CP4 |
| Templates drift from what skills produce | C10 harness validates required sections |

## Evals that cover it
C10 harness structural checks on every eval run; validator unit tests.

# /qml-prereg — essence

**Job.** Decide what counts as success before any data exists, in a form a machine can check later:
were the gates the same before and after the data was opened?

## Judgment calls
- **Which phases, in which order.** The analytic resource count (P0) first, then the run phases the
  hypotheses need, cheapest fatal gate first.
- **What the classical side is.** The best method for the task, the strongest exact method and the
  twin, each tuned with at least the quantum budget, with a measured adequacy bar.
- **What each gate means.** A justified threshold, a curve across the resource range with a minimum
  gain that matters, a size-matched control where a gate could pass for the wrong reason, a
  gray-zone policy, and both verdict sentences.
- **Who reads it.** A person gets the program from the plan in five minutes: why each experiment
  is there, what it can end and what it costs. An implementer runs one experiment from its own
  document without reading the others. History lives in the change log, not in either.
- **Whether a human freezes it.** Always. Freeze is where framing errors are caught.

## Success
A different agent could run every phase without asking a question, another could audit it
mechanically, and the panel's blocking issues were fixed before freeze.

## Failure it guards against
Post-hoc redefinition of success, single-point comparisons, weak baselines, unplanned controls, and
simulator time standing in for quantum time.

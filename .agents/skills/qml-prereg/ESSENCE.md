# /qml-prereg — essence

## What this skill is for
Deciding what counts as success before any data exists, in a form a machine can check later.
Everything about trusting a negative reduces to one question — were the gates the same before
and after the data was opened? — and this skill makes that a hash comparison instead of a
careful re-read.

## The judgment calls it makes
- **Which phases, in which order.** Adi's ladder (toy → medium → real data + industrial
  extrapolation → noise → hardware plan), ordered so the cheapest fatal gate fires first.
- **What the classical side is.** The twin, the strongest exact method, the tool industry actually
  runs — each tuned with at least the quantum arm's budget, with a measured adequacy bar.
- **What each gate means.** A threshold with a justification, a curve across the resource axis,
  a size-matched control where a gate could pass for the wrong reason, a gray-zone policy, and
  both verdict sentences — written now.
- **Whether a human should freeze it.** Always, in this version and permanently: freeze is where
  framing errors are caught, and no automated check catches a well-gated experiment on the wrong
  question.

## What success looks like
A different agent could run every phase without asking a question, a different agent could
audit it mechanically, and the panel found nothing blocking — or found it, and it was fixed
before freeze.

## The failure it guards against
Post-hoc redefinition of success; single-point comparisons; weak or untuned baselines; controls
that were never planned; and simulator time quietly standing in for quantum time.

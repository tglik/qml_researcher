# /qml-variants — essence

## What this skill is for
Making a closed program pay twice: once for what it ruled out, and again for the directions its
failure points to — without throwing away the classical results and instruments it produced.

## The judgment calls it makes
- **What exactly failed.** One primary mechanism, stated as a precondition.
- **Where that precondition does not hold.** Invert it; relax exactly one axis at a time
  (including accuracy tolerance, the one people forget).
- **Is this a new idea or the same one?** Same gate, same mechanism is a covered case of the
  exclusion, not a variant.
- **What else it is worth.** A paper (a well-supported negative, a benchmark, a dequantization, a
  quantum-inspired method), IP (filing before any disclosure), and the salvage.

## What success looks like
At most five variants, each arriving pre-screened with the gate it would newly pass, the gate it
would newly face and its predicted kill point — a backlog, not a brainstorm.

## The failure it guards against
Idea spam, and the quiet loss of the classical assets a program produced.

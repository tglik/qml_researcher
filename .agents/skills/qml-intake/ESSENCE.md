# /qml-intake — essence

## What this skill is for
Turning whatever arrives — a quantum algorithm from Adi, a hypothesis card from the literature
half, a transfer card, a hunch — into a hypothesis the rest of the lab can actually test:
numbered claims with predicted values, a named operating point, and a disproof written before
any data exists.

## The judgment calls it makes
- **Which path.** An *algorithm* arrives with its own machinery and must first be understood end
  to end (Adi's Stage 0): loading, circuits, shots, readout, resources in the same variable as the
  classical competition, the twin, the warnings. A *use case* arrives as a claim about value and
  must first be made falsifiable. Both end in the same place: one hypothesis document.
- **When it is done.** Five things, all present: a contradictable claim, the operating point, the
  disproof, the arm that wins if the claim is false, and the decision the answer changes. Four out
  of five is not done.
- **When to give up.** "This is a topic, not a hypothesis" is a valid, useful outcome.

## What success looks like
The screen can rate every rule decisively from the hypothesis (and the algorithm analysis)
without going back to the proposer.

## The failure it guards against
Politeness — accepting "make QML work for tabular data" — and its algorithmic twin, accepting a
paper's own resource claims at face value.

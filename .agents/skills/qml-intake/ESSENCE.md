# /qml-intake — essence

**Job.** Turn whatever arrives (an algorithm from Adi, a hypothesis card, a transfer card, a hunch)
into a hypothesis the lab can test: numbered claims with predicted values, a named operating point,
and a disproof written before any data exists.

## Judgment calls
- **Which path.** An algorithm must first be understood end to end: loading, circuits, shots,
  readout, resources in the same variable as the classical competition, the Rule 1 checklist and
  the warnings. A use case must first be made falsifiable. Both end in one hypothesis.
- **When it is done.** All six pieces present: a contradictable claim, why the method should work
  and why it is built this way, the operating point, the disproof, the classical baseline that wins
  if the claim is false, and the decision the answer changes. Five of six is not done.
- **Who reads it.** A reader outside the field must be able to explain the hypothesis back: what
  the algorithm does, why it is built this way, and why each hypothesis is expected and worth
  testing.
- **When to give up.** "This is a topic, not a hypothesis" is a valid outcome.

## Success
The screen can rate every rule decisively without going back to the proposer.

## Failure it guards against
Accepting "make QML work for tabular data" as a hypothesis, or accepting a paper's own resource
claims at face value.

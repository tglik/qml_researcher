# /qml-study — essence

**Job.** Run one small study on one backlog idea, in hours, so that the result is trustworthy
without a person checking each step. A study is a step, not a program: it answers one falsifiable
question, usually a bet's cheapest fatal test, and leaves a frozen bundle others can build on.

## Judgment calls
- **Is the question small enough?** One claim, one operating point, one classical baseline. If it
  needs phases, it belongs in the full lab instead.
- **Did the critique change anything?** Say so honestly. A critique that changed nothing is still
  recorded; the debrief counts how often critique mattered.
- **Is the objection real?** An objection counts only once it runs as code against the outputs.
  Text that cannot be run is a note, not an objection.
- **Does the code do what the title says?** Read it line by line before release. Answer keys,
  leaked targets and overwritten failures look like results.
- **What does the number actually show?** A non-significant result is not proof of no effect.
  Say the bounded thing.

## Success
A released study whose every reported number traces to a file, whose design was challenged before
it ran, and whose abstract claims no more than the outputs support. A clean null counts in full.

## Failure it guards against
Rigor without relevance, and relevance without rigor. The agent community this copies was rigorous
but chose narrow problems; the ideas here come from the backlog, and the debrief judges whether
each study moved a direction toward an algorithm we would own. It also guards against herding:
the author never sees rankings or other studies' scores while choosing a design.
